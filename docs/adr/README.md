# 架构决策记录（ADR）

本目录存放 phaser-mvvm 的架构决策记录。**`docs/PLAN.md` 是唯一事实来源**：ADR 只解释「为什么这样定」，不引入 PLAN 之外的决策；若二者出现冲突，以 PLAN.md 为准并提 issue 修正。

- 状态取值：`Accepted`（已采纳，执行中）、`Superseded by ADR-XXXX`（被替代）、`Deprecated`（不再推荐）。
- 日期为决策月份（当前全部为 `2026-09`，对应 PLAN v1.1 的两次评审）。

## 规则

1. **新决策必须新增编号，不得修改历史 ADR 的「决策」部分。** 需要变更既有结论时，新建 `NNNN-<slug>.md`，并把旧文档的状态改为 `Superseded by ADR-XXXX`（只加状态行，不改历史正文）。若只是**代码里的名字或边界变了、决策本身没变**（函数改名、选项改名、某个目录被摊平），同样不改历史正文，改为在该篇文末的「现状校正」小节里就地标注。
2. 编号连续、四位数字、kebab-case 短标题（例如 `0011-theme-token-model.md`）。
3. 每篇必须包含固定小节：`状态`、`日期`、`背景`、`决策`、`理由与权衡`、`后果（正面/负面）`、`相关`。**0009 起改用更短的版式**：`状态`、`相关`、`背景`、`决策`、`后果`、`证据`（「相关」也允许指向 ADR 与源码文件，不强制指向 PLAN 章节）。
4. 0001–0008 的「相关」指向 PLAN.md 的具体章节号；不在 ADR 中复制 PLAN 的表格内容，只引用。
5. 新增发布包、引入新的运行时依赖、改变包间依赖方向 —— 这三类改动**必须**有 ADR。
6. ADR 一经 `Accepted` 即为评审依据：里程碑验收若与 ADR 冲突，先改 ADR（新增编号）再改代码。
